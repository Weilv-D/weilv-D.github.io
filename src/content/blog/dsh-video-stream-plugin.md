让大语言模型看视频时，如果只是简单粗暴地均匀抽帧，往往会出不少问题。关键动作很容易掉进采样间隔里，切镜容易被漏掉，静态图也跟不上台词的时间线。如果靠疯狂增加截图密度来解决，不仅 API 账单会原地爆炸，模型的上下文也会瞬间被撑爆。

为了在预算红线内解决这个痛点，我为 DSH 平台开发了 dsh-pf-stream 插件。它的核心思路很务实：充当大模型的视觉前置过滤器，在不超支的前提下，把视频里信息量最高的画面挑出来，连同时间戳、坐标和文字一起交给模型。这篇文章将聊聊它的底层设计，以及在宿主环境下的工程取舍。

## 平台环境的工程约束

落地视频解析，首先要面对三道现实的门槛。

第一是 Token 太贵，十分钟的视频哪怕低频抽帧，图片成本依然极高，无差别截图根本不划算。第二是时间轴对不齐，可变帧率和 B 帧的存在，让单纯的帧号无法精准对应真实的播放时间。第三是 DSH 平台的沙盒契约：工具必须单次调用就返回，单轮通信最多带 20 张图，且输出内容必须是合法的 JSON。

既然常驻后台的流媒体服务走不通，插件干脆采用了“一次请求处理一个时间窗”的无状态模式。每次只管当前片段，遇到异常直接回滚。后续指令靠时间戳（PTS）锚点断点续传，彻底省去了复杂的内存状态维护。

## 剔除废片的能量积分机制

大多数视频里有大量静止或无意义的运镜画面，一直截图纯属浪费算力。为了过滤掉这些废片，解码器引入了“梯度能量差”：把相邻画面的差异度跟时间间隔相乘，累加进一个积分器里（统一按 30fps 换算，防止高帧率视频误判）。用积分代替单帧阈值，既能攒出缓慢的平移运镜，又能像滤网一样屏蔽单帧的噪点干扰。

这个机制由一个四态机控制，配合双阈值防抖。积分超限时，系统会密集生成低分辨率的过程图（P 单元）；画面稳住后，系统会在窗口期内挑一张对焦最实、没有拖影的高清定格图（F 单元），而不是随便抓第一帧。遇到切镜，直接清空累积状态并锁定新场景，防止前后画面的特征串味。

## 契合计费步长的网格化画布

因为平台限制单次最多发 20 张图，直接把 P 单元和 F 单元全发出去肯定会超载。为此，插件做了一套动态拼图机制。

关键细节是：所有画面的尺寸必须严格对齐 42 像素的整数倍。这个数字不是拍脑袋决定的，而是顺着 DSH 官方视觉 Token 的计费步长来的。对不齐的图片会在云端被强制重采样，既浪费钱又会让画面变糊。

以标准的 FORM_1 模板为例，它能把四张记录动作的过程图和一张高清定格图拼在一张大图里。这不仅省了 Token，还把离散的时间切片在空间上聚拢，大大减轻了模型理解时间线时的脑力负担。

为了防止 AI 把拼图当成奇怪的真实场景，小图之间都加了高对比度的隔离线和反色编号。同时，数据包里会带上详细的结构化信息，告诉模型哪个编号对应什么时间、在什么位置，让模型的回答有据可查。

## 动态自适应微调

死板的参数搞不定复杂的真实视频。所以系统底层加了个控制器，每 500 毫秒根据画面动态微调：

遇到高频闪烁光源，赶紧拉高判定门槛过滤干扰；遇到慢动作推镜头，就适度调大积分池，防止过程图泛滥；遇到剧烈摇晃，自动延长冷却期防刷屏；碰到连续切镜，则缩短观察期去抓关键帧。这些调整都做了一阶平滑过渡，保证输出节奏不突兀，并且会在日志里留下控制标记，方便后期排查。

## 不打断 KV-Cache 的滚动内存池

视频太长，不可能把所有截图都留在上下文里。插件用了一套类似滑动窗口的淘汰机制：最新的高清画布留在“热区”，稍旧的数据折叠进“冷区”（只留少量高清定格图），更早的历史则干脆变成纯文本。

这里有个绝对不能碰的红线：为了保住大模型的 KV-Cache 命中率，历史图片在多轮对话中绝对不能被重绘。一旦字节发生变化，缓存直接断裂，推理延迟和计费都会瞬间飙升。面对单次传输 56 MiB 的容量上限，系统制定了严格的丢弃顺序，一旦截断，还会用文字提醒模型当前的时间点，引导它自己继续往下查。

## 成本优先的异步 Sidecar 音频机制

在处理台词音频时，省钱是第一原则。系统采用阶梯式策略：先找免费且时间轴最准的外挂或内嵌字幕；找不到再上 VAD（人声检测）跳过纯静音片段；最后没办法了，才把音频切块交给 ASR 模型转文字。

因为语音转录非常耗时，如果非要音画同步，整个解析流程就会卡死。于是系统引入了 Sidecar（旁路伴随）模式：画面搞定就先发给模型，耗时的音频转录放在后台静默跑。等模型发起下一轮对话，再把转录好的文字贴上去。这样一来，昂贵的音频解析就绝不会拖慢核心的视觉处理节奏。

## 规避压缩的确定性降级

自动过滤虽然能理清视频的主线，但在面临“看清屏幕上的小字”或“读仪表盘读数”这种细节任务时，画面压缩必然会导致信息丢失。

为了兜底，插件提供了三条完全确定的后备指令：零视觉开销的元数据读取、基于精准毫秒定位的局部高倍裁切，以及强硬的等距切片。当拼图不够清楚时，模型可以自己调用这些工具去局部复查，在宏观理解与微观细节之间取得平衡。

## 无原生依赖的纯 JS 运行时

因为是跑在 DSH 里的插件，底层必须守规矩。入参必须是极简的 JSON Schema，密钥也得走官方指定的通道。

最要命的是，为了防止跨平台部署时引发 Node ABI 崩溃，项目里连一条 C++ 原生扩展都不能有。所以画面的裁剪、拼接和渲染，全靠 pngjs 这种纯 JavaScript 库硬扛。项目的 CI/CD 流水线里也加上了严格的契约校验，代码稍有违规就会在构建期被拦下。

## 总结

dsh-pf-stream 的核心工作就是包揽视频抽帧、时空对齐和画布打包的脏活累活，把结构化的干净数据交给大模型去推理。该插件目前已基于 Apache-2.0 协议开源。如果你想在本地环境尝试这套流式解析方案，或进一步了解其运行的宿主环境，可以通过以下链接获取源码：
